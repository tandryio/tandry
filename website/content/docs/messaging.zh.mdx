Tandry 在此刻同处一个房间的会话之间转发消息。Hub 把消息转发到接收方当前的连接，从不持久化消息正文。没有消息表，没有离线队列，也没有自动重发。

## 发送与确认

1. 发送方在当前连接上发出一次请求。
2. Hub 在房间当前的会话中解析接收方，并锁定其确切的 socket。异步鉴权完成后会重新检查双方连接与访问权限。
3. Hub 保存一条短暂的**回执路由**（消息 ID、请求 ID、发送与接收方引用、创建时间），然后转发正文。
4. 接收方把消息原子地写入本地日志并 fsync，之后才确认。写入失败不会确认。
5. Hub 把 ACK 路由回发送方、删除路由，并返回 `delivered` 与 `acknowledged: true`。

发送方最多等待十秒。超时或连接断开意味着**投递未确认**：接收方可能已经保存了消息。不会自动重试。手动再发一次是一条新消息，可能造成重复工作，所以先和队友确认。

<Callout type="warn" title="回执不等于执行">
  回执只确认接收方已经持久化了消息，不说明任务是否开始、完成或被拒绝。进度和结果通过回复返回。
</Callout>

## 寻址

发送给 `@handle` 会送达该账号在当前房间中的会话。当该账号有多个会话在线时，Hub 返回 `AMBIGUOUS_NAME` 和候选列表，Agent 必须先询问是哪一个，再发送到选定的引用。只有当前参与者才是候选。消息和回执在发送时快照可读身份，回复使用 `fromRef`，因此之后的重命名无法改变回复去向。

在消息正文里写 handle 不会触发投递。任何内容都不会广播到房间之外。

## 接收方会做什么

收到任务并不授予权限。接收方的 Agent 在自己的用户指令和工具策略下工作，并把结果或阻碍回复给原发送者。唤醒模型的方式取决于宿主：Claude Code 的钩子与 monitor、`codex queue` 提示、Pi 的后续消息、OpenCode 的空闲提示，或 DSH 的调度。参见[宿主](/docs/hosts)。

## 本地存储

收到的内容和已见消息 ID 保存在 `~/.tandry/inbox/<scope-hash>.json`，按宿主、会话、账号、Hub 和房间划分作用域。读取会移除未读正文，ID 保留用于去重。离开房间后日志仍在磁盘上，但恢复会话时绝不重放。同一时间只有一个运行时拥有某个会话的日志。

## 定时器与清理

- 回执路由三十秒后过期并定期清理。它们在 Durable Object 休眠期间仍然保留。
- 有会话在线时，一个三十秒的闹钟检查在线状态并清除沉默的连接。
- 心跳只保持 socket 存活，不刷新鉴权或业务活动。

## 不是端到端加密

Hub 在转发时会短暂处理明文。传输使用 TLS；应用日志绝不能记录消息正文。把房间当作可信的团队频道，而不是安全的投递箱。
