# Website internationalization

The website uses **Paraglide JS**, following the [TanStack Start integration](https://tanstack.com/router/latest/docs/guide/internationalization-i18n).
Paraglide is a third-party library integrated with TanStack, not an i18n engine built into TanStack.

## Language and rendering

- English (`en`) is the base and default language. Simplified Chinese (`zh`) is available from the navigation language selector.
- Paraglide resolves `cookie → baseLocale`; it deliberately does not infer language from the browser. The `agent-room-locale` cookie preserves an explicit choice.
- Switching languages reloads the current URL, retaining its path and query parameters. Unsaved form edits are not retained across that reload.
- There are no locale URL prefixes. Login callbacks and device links keep their existing addresses.
- `website/src/server.ts` wraps the TanStack handler in `paraglideMiddleware`. Request-local language state supports concurrent SSR without sharing preferences between users.
- The HTML `lang`, title, description, and page content use the same locale. Cookie-selected HTML varies on `Cookie` and is marked private to avoid shared-cache language mixups.

## Adding text

Edit `website/messages/en.json` first, then add the same key to `zh.json`. Use stable, descriptive keys and complete messages with named parameters:

```json
"email_code_sent": "Code sent to {email}. It expires in 10 minutes."
```

Use the compiled function in a component:

```tsx
import { m } from "../paraglide/messages";
<p>{m.email_code_sent({ email })}</p>
```

The Vite plugin compiles catalogs and TypeScript declarations into ignored `website/src/paraglide/` during development/build. Do not edit generated output. A fresh checkout must run `pnpm website:build` before type checking. Settings live in `website/project.inlang/settings.json` and `website/vite.config.ts`.

Dates use the active locale. Known API errors are mapped at the UI boundary in `src/lib/i18n.ts`, by stable `code` where the Hub provides one and by message otherwise; unknown upstream error messages remain as supplied. User-written names, handles, room names, messages, and literal CLI commands are not machine-translated. Brand slogans remain in English. The Hub's small email template uses the same locale cookie, defaulting to English.

## Profile entry points

The navigation's **Profile** link opens `/account`; after a handle is set, it shows `@handle`. The profile page displays the avatar, editable display name, email, handle, permanent account ID, linked providers, and sessions. A handle is chosen once, right after the first sign-in; `/account#handle` shows the claim form until then and the existing handle afterwards. Handles remain unique and cannot currently be renamed.

## Validation

Run `pnpm website:build`, `pnpm typecheck`, and `node --test website/scripts/i18n.test.mjs`. Tests check catalog keys and parameters, English fallback, and concurrent SSR locale isolation. Browser QA should cover language persistence after reload, profile setup, narrow layouts, and the device URL's `next` query. Use isolated or mocked accounts instead of changing personal profiles during tests.
