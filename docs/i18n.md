# Website internationalization

The website uses **Paraglide JS**, following the [TanStack Start integration](https://tanstack.com/router/latest/docs/guide/internationalization-i18n).
Paraglide is a third-party library integrated with TanStack, not an i18n engine built into TanStack.

## Language and rendering

- English (`en`) is the base and default language. Simplified Chinese (`zh`) is available from the navigation language selector.
- Paraglide resolves `cookie → baseLocale`; it deliberately does not infer language from the browser. The `tandry-locale` cookie preserves an explicit choice.
- Switching languages reloads the current URL, retaining its path and query parameters. Unsaved form edits are not retained across that reload.
- There are no locale URL prefixes. Login callbacks and device links keep their existing addresses.
- `website/src/server.ts` wraps the TanStack handler in `paraglideMiddleware`. Request-local language state supports concurrent SSR without sharing preferences between users.
- The HTML `lang`, title, description, and page content use the same locale. Cookie-selected HTML varies on `Cookie` and is marked private to avoid shared-cache language mixups.

## Adding text

Edit `packages/web/messages/en.json` first, then add the same key to `zh.json`. Keys are namespaced by page or concern (`meta_`, `nav_`, `common_`, `error_`, `landing_`, `install_`, `faq_`, `login_`, `connect_`, `device_`, `rooms_`, `account_`, `handle_`, `privacy_`); the catalog test rejects other prefixes. Prefer one complete message with named parameters over concatenated fragments:

```json
"login_email_code_sent": "Code sent to {email}. It expires in 10 minutes."
```

Use the compiled function in a component:

```tsx
import { m } from "../paraglide/messages";
<p>{m.login_email_code_sent({ email })}</p>
```

Split a message only when markup must sit inside it (for example the highlighted half of the hero title); join the parts with an explicit space in JSX so hidden line breaks never glue words together.

`pnpm --filter @tandryio/web build` compiles catalogs and TypeScript declarations into ignored `packages/web/src/paraglide/` during development/build. Do not edit generated output. A fresh checkout must run `pnpm website:build` before type checking. Settings live in `packages/web/project.inlang/settings.json` and `packages/web/scripts/build.mjs`.

Dates use the active locale. Known API errors are mapped at the UI boundary by `errorText` in `src/lib/i18n.ts`, by stable `code` where the Hub provides one and by message otherwise; unknown upstream error messages remain as supplied. Pass the thrown value itself (an `ApiError` keeps its `code`), not `error.message`. `useAction` in `src/lib/action.ts` already does this for user-triggered requests. User-written names, handles, room names, messages, and literal CLI commands are not machine-translated. Brand slogans and the numbered section kickers on the landing page remain in English; app-page kickers are translated. The Hub's small email template uses the same locale cookie, defaulting to English.

## Profile entry points

The navigation's **Profile** link opens `/account`; after a handle is set, it shows `@handle`. The profile page displays the avatar, editable display name, email, handle, permanent account ID, linked providers, and signed-in devices. A handle is chosen once, right after the first sign-in; `/account` shows the claim form inline until then and the existing handle afterwards. Handles remain unique and cannot currently be renamed.

## Validation

Run `pnpm website:build`, `pnpm typecheck`, and `node --test website/scripts/i18n.test.mjs`. Tests check catalog keys and parameters, English fallback, and concurrent SSR locale isolation. Browser QA should cover language persistence after reload, profile setup, narrow layouts, and the device URL's `next` query. Use isolated or mocked accounts instead of changing personal profiles during tests.
